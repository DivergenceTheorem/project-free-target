# Проект "Free target"

## Задача

Создать модель машинного обучения для анализа данных кредитного портфеля и выявить, какая коммуникация наиболее эффективно приводит к возобновлению платежей клиентами с просроченными долгами.

Цели проекта:
- Выявить типы коммуникаций, которые больше всего способствуют возобновлению просроченных платежей
- Построить модель, которая способна "предсказать" исход коммуникаций
- Оценить эффективность построенных моделей для различных категорий клиентов

## Данные

`dataset.csv`: 769 582 записей, 78 параметров. Файл не хранится в репозитории (см. `.gitignore`). Весь код находится в `main.ipynb`.

## Что было сделано

**1. Exploratory Data Analysis.** Убрали параметры, чье влияние минимально, которые напрямую коррелируют с другими, практически не меняются или не имеют внятной интерпретации (например, `currency`, `customer_id`, `row_num`, `sign_ref`). Итого: 19 параметров.

**2. Data preprocessing**
- Оставили только договоры, у которых была хотя бы одна просрочка (`delay_count_main` ≠ 0)
- `delay_count_main` и `next_payment_date` заполнили, используя данные из смежных параметров
- Удалили ряды, где пусты все 3 ключевых параметра
- `attr_gender_categorical`, `attr_city_categorical`: вероятностное заполнение по распределению параметра
- `attr_age`, `attr_chld_cnt`: замещение медианой (-1 и выбросы ≥ 10 → пропуск)
- Сортировка датасета по `contract_number`, `comm_date`

**3. Выбор целевой метрики**
- `is_reduced` = 1, если задолженность снизилась после уведомления, иначе 0
- Последовательность (sequence): набор из 1 и более последовательных уведомлений внутри договора. Каждая последовательность начинается либо с нового кредита, либо с элемента, у которого `is_reduced` = 1
- Если последовательность уведомлений снизила долг, она считается завершенной (Complete, "1"), иначе незавершенной (Incomplete, "0")
- Целевой параметр: `sequence_status`

**4. Датасет для моделей (как избежать утечки целевого параметра)**
- Незавершенные последовательности всегда идут последними в договоре, их обрывает конец выгрузки. Поэтому длина цепочки выдает класс
- Модели видят только первые 5 уведомлений последовательности (`n_first_actions = 5`). Берем последовательности, в которых не меньше 5 уведомлений: 46 653 шт. (25 961 Incomplete / 20 692 Complete)
- Результаты звонков (OK, Answer, Wrong Party, No Answer и т.д.) являются ответами клиента, а не типом коммуникации, поэтому все звонки заменены на одно действие `Call`
- Train/test (80/20) делим по договорам (`GroupShuffleSplit`): последовательности одного клиента не попадают одновременно в обучение и тест

**5. Построение моделей**
- **Логистическая регрессия**: one-hot encoding уведомлений, группировка по последовательностям, SHAP-explainer, оценка по категориям клиентов (пол, возраст, длина последовательности)
- **XGBoost**: pivoted data (порядковый номер действия как новый параметр) + признаки клиента и договора
- **Random Forest**: тот же датасет, категории через `LabelEncoder`
- Сравнение с базовыми моделями: случайная классификация и мажоритарный класс

## Выводы и рекомендации

- PUSH/SMS-уведомления, отправляемые в 1-5 день, имеют самый значимый эффект, но разные шаблоны действуют в разные стороны. Это может быть связано и с другими факторами: обычно клиенты стараются закрыть задолженность в кратчайшие сроки вне зависимости от уведомления. **Рекомендация:** попробовать сократить количество уведомлений в первые пять дней и посмотреть, насколько они влияют на выплату задолженности.
- XGBoost и Random Forest с умеренной точностью (ROC-AUC ≈ 0.67) определяют, будет ли последовательность уведомлений успешной. Модель может принять на вход планируемую цепочку уведомлений и ряд характеристик клиента и классифицировать ее с точностью около 64%. **Рекомендация:** с помощью модели составить стандартизированные цепочки уведомлений для разных категорий клиентов. Необходима дальнейшая работа с выборками из различных категорий.

## Ограничения

- Незавершенная последовательность, оборванная концом выгрузки, могла бы завершиться позже
